## Resulting behavior and boundaries

- Recipe and ingredient editing belongs in Recipes. Menu review changes recipe selection, optional dessert and eating-out details; the dedicated recalculation action resizes existing editable portions to current budgets.
- Saved meals retain their own recorded references. Vetoing or editing a catalogue recipe does not silently replace existing meals. Household diet/exclusion validation and approved recipe-specific substitutions still apply.
- Budget allocation may leave a margin below the daily target. Displayed equality does not trigger an excess warning. Planned calories enter known intake at the person's configured meal times.
- History records confirmed operations and their actual effects, including planning inputs. It excludes uncommitted previews and failed writes. The compact presentation changes how evidence is read, not what is stored. Earlier ordinary edits cannot be reconstructed; only available historical correction evidence is imported.
- Existing Google authentication, isolated households, personal ownership of profile/budget/log writes, closed-day protections, shared lunches/dinners and offline shopping synchronization continue to apply. V5 introduces no pantry, photos, guests or concurrent membership in multiple households.

Continue using the existing Node 24 / Cloudflare Pages build and public Supabase configuration. V5 adds no environment variable or paid dependency. Source merge, hosted SQL, Cron configuration, deployment and installed-PWA updates are distinct steps; this documentation change performs none of those external operations.
