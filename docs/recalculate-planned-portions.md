# Recalculate planned quantities

The Menu toolbar includes a calculator action, **Recalculate quantities**, for the currently viewed week. It loads a coherent household snapshot containing current budgets, targets, saved meal portions and their ingredient dependencies, then prepares a review. **Apply quantities** saves all changed meals in one existing `apply_meal_plans` call with revision protection. No new database migration or public API is required.

The calculation considers each existing home-cooked portion separately, including shared lunch/dinner portions and each person's breakfast. The effective budget for that person, date and meal uses an individual override first, otherwise the accepted target's defaults. It does not add meals or participants, change recipes, reset substitutions, change dessert choices, or copy newer saved recipe content into planned snapshots.

Ingredient calories are recalculated from the current nutrition catalogue. If displayed calories differ from the current budget, existing ingredient quantities are scaled proportionally, preserving manual ingredient ratios, component identifiers and units. Existing practical rounding rules apply, including ingredient-specific unit steps (with a minimum positive step) and tiny seasoning quantities. A rounded candidate is used only if it is strictly closer to the budget; this avoids worsening a manually adjusted portion or flipping equally good quantities back and forth. Some budgets cannot be matched exactly with practical units. The review explains remaining rounding differences, and an unchanged result is not submitted.

Eating-out calorie entries are not resized. Closed dates, including a date already ended for another active household member, and dates outside the viewed week are excluded. Current household dietary restrictions still apply; missing nutrition, invalid budgets or other validation failures do not cause a partial save. Original input state is never mutated while preparing a draft. Existing non-calorie warnings are retained.

The review shows the date, meal, member, recipe, old/new calories and current budget. Saving uses the snapshot's household revision. If another edit wins first or a day closes before saving, the existing server rejects the batch and the review shows an inline error. It does not automatically retry or overwrite the newer edit. Successful saves use the existing automatic shopping reconciliation, including quantity increases unchecking generated items and preservation of manual additions. Targets, profiles and historical records are not changed.

Verification includes client regressions for over/under-budget scaling, personal overrides, substitutions/desserts, manual composition, whole units, rounding-limited no-ops, earliest-member cutoff, restaurant entries and missing nutrition. Database coverage saves the generated batch through the real household RPC, verifies stale-review rejection and unchanged unrelated plans/targets, and checks automatic shopping quantity/check updates. Browser coverage changes daily budgets after a week is saved, reviews the recalculation without writing, applies it and checks preserved recipe/ingredient selections and updated shopping.
