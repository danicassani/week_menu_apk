# Planned meal review

The saved-meal review selector excludes archived recipes, recipes vetoed in the household and recipes for other meal types. Existing saved snapshots are retained if their recipe is later vetoed; the selector shows a disabled prompt to choose an available replacement rather than offering that vetoed recipe. Returning from eating out uses the same filtered candidates. An empty set is explained inline.

Selection errors appear beside the affected person's selector and receive focus and scroll into view. Save errors remain in the open dialog at its start and receive focus too. Portion failures name the recipe, affected person and ingredient. They distinguish explicit exclusions from dietary incompatibility, absent recipe-specific substitution rules, and configured substitutes that are missing, archived, excluded or incompatible. Missing/archived ingredients and missing calorie data also identify the ingredient. Errors received without details explicitly say that no concrete cause was provided instead of claiming that the recipe does not exist. Revision changes still require reloading the meal; failed choices keep the previous draft.

Reviewing a meal allows changing its recipe, optional dessert and eating-out details. Ingredient quantities are shown read-only and are calculated from the person's meal budget when choosing a recipe. Use the menu's Recalculate quantities action for existing budget changes. Edit a recipe and its reference ingredient amounts through Recipes → Edit recipe. Saving a meal no longer offers to overwrite its recipe; the obsolete recipe-update-prompt settings have been removed from the profile. Existing persisted prompt preferences and API signatures are retained for older clients.

Substitution notes now say only “Replace X with Y” / “Sustituye X por Y”, using translated ingredient display names. This applies to suggested meals, saved-meal review, meal snapshots, transfer review and offline snapshots. Stored substitution metadata and recipe cooking instructions are unchanged. Historical correction is a separate audit workflow and retains its existing controls. No database migration is required.
